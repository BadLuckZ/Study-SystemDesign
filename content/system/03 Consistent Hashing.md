ปกติแล้ว ถ้าระบบเรามีคนใช้งานเยอะขึ้น มันก็ต้องมีการทำให้ Server สามารถรองรับการใช้งานได้มากขึ้น วิธีนึงที่เลี่ยงไม่ได้ คือการซื้อทรัพยากรมาเพิ่ม ไม่ว่าจะเป็น Vertical Scaling อย่างการเพิ่มประสิทธิภาพ CPU แต่ว่าก็จะมีขีดจำกัด เลยนำมาสู่ Horizontal Scaling อย่างการซื้อ Server เพิ่ม

ปัญหาอยู่ที่ Horizontal Scaling นี่แหละ เพราะว่า Server ใหม่มันไม่มีข้อมูล คำถามคือเราจะกระจายข้อมูลจาก Server ทั้งหมดที่เรามีมาให้กับ Server ใหม่ยังไงไม่ให้การใช้งานของ User มันแย่ลง

## Problem Statement

ถ้าสมมติว่าเราใช้วิธีการปกติอย่าง Hashing ธรรมดาๆ อ่ะ

ถึงต่อให้ตอนนี้เราจะสร้าง Hash Function ให้สามารถกระจายข้อมูลให้กับทุก Server ได้อย่างสมดุลกันแล้วก็ตาม แบบในภาพ A (Server 4 ตัว) พอถึงวันที่ Server ตัวนึงมันพัง หรือจะต้องซื้อ Server เพิ่ม ก็ไม่มีอะไรการันตีเลยว่า Hash Function เดิมของเราจะกระจายข้อมูลได้สมดุลอีก แบบในภาพ B (Server 3 ตัว)

---

## Proposed Solution

ก่อนอื่นเลย อะไรคือ Consistent Hashing...

Consistent Hashing คือการที่เมื่อมีการเพิ่ม / ลด Server จะต้องมีข้อมูลเพียง k / n ตัวที่ต้องขยับไปอยู่ใน Server ใหม่ แล้วยังทำให้ทุก Server มีข้อมูลที่สมดุลกัน เมื่อ k คือจำนวน keys ที่มี และ n คือจำนวน Server ที่เหลืออยู่

วิธีการที่ทำได้การใช้ Concept ของ Hash Ring
![[hash_ring.png]]

Hash Ring คือการนำค่าจาก Hash Function มาเรียงกันเป็นวงกลมจากน้อยไปมาก

สมมติว่าเรามี key k ตัว จาก 0 ถึง k-1 ที่นำค่าที่ได้จาก Hash Function มาแปะใน Hash Ring แล้วจากนั้นนำ key ของ server ที่มีมาผ่าน Hash Function แล้วใส่เข้าไปใน Hash Ring แล้วเรียงข้อมูลได้ดังรูปข้างบน

การจะหาว่า key ตัวใดอยู่ที่ Server ใดคือใช้หลักงานง่ายๆ เลย
1. หาว่า Key ที่เราสนใจอยู่ตรงไหนของ Hash Ring
2. ไล่ตามเข็มนาฬิกาไปเรื่อยๆ จนเจอ Server

จากภาพข้างบนก็จะได้ว่า k0 อยู่ใน server 0 เป็นต้น

| ![[hash_ring_add_server.png]]<br><br>ภาพ C | ![[hash_ring_remove_server.png]]<br><br>ภาพ D |
| :----------------------------------------: | :-------------------------------------------: |
|                                            |                                               |

เวลาเพิ่ม Server ใหม่ตามภาพ C (เพิ่ม Server 4) ก็สามารถทำได้ง่ายๆ ผ่านการเอาค่าจาก Hash Function ที่ใช้ key ของ Server ใหม่เป็น Input ไปใส่ใน Hash Ring จากนั้นก็ไล่ข้อมูลทุกตัวว่าจะต้องไปอยู่ใน Server ใหม่ หรือยังอยู่ใน Server เดิม

หรือเวลาลด Server ใหม่ตามภาพ D (เอา Server 1 ออก) ก็สามารถทำได้ง่ายๆ ด้วยการเอา Server ดังกล่าวออกจาก Hash Ring ไป จากนั้นก็ไล่ข้อมูลทุกตัวว่าจะต้องไปอยู่ใน Server ใหม่ หรือยังอยู่ใน Server เดิม

### ปัญหาของวิธีนี้ คือ มีโอกาสที่บาง Server จะถือข้อมูลเยอะกว่า Server อื่นๆ เวลาเพิ่ม / ลด Server หรือแม้แต่กระทั่งสถานการณ์ปกติที่ไม่มีเพิ่ม / ลด Server แต่ข้อมูลมันดีเกิน มันไปกระจุกใน Server เดียว

แล้วเราจะแก้เรื่องนี้ยังไง... ใช้ Virtual Nodes สิ

![[hash_ring_virtual_nodes.png]]

คิดภาพง่ายๆ ว่า เหมือนเอา Server ใหญ่มาทำเป็น Server ย่อยๆ หลายๆ ตัวอ่ะแหละ

เช่นใน Case นี้คือเรามี Server 2 ตัว คือ Server 0, Server 1 แล้วเราทำเป็น Server ย่อยรวม 6 ตัว คือ Server 0_0, Server 0_1, Server 0_2, Server 1_0, Server 1_1, Server 1_2 โดยพยายามทำให้ Server ย่อยๆ จาก Server หลักอยู่คร่อมกัน ตามรูป (Server 1 สลับ Server 0 สลับไปมาเรื่อยๆ)

แล้วพอเวลาหาว่า Key นี้อยู่ที่ Server ใด ก็ไล่เหมือนกับ Hash Ring ปกติเลย ก็จะทำให้เพิ่มโอกาสที่ข้อมูลจะอยู่ในทุก Server อย่างสมดุลขึ้น เพราะตำแหน่งของแต่ละ Server อยู่กระจายๆ กันไป ยิ่งมีเยอะก็ยิ่งเพิ่มโอกาสให้ข้อมูลอยู่ในทุก Server อย่างสมดุล

เวลามีการเพิ่ม / ลด Server ก็ใช้หลักการปกติได้เช่นเดียวกัน!
